# 阶段一：一条消息如何走完整条链路

先读 `main.py`：它现在只负责组装和启动。这叫“职责分离”：你想改教学方式就找提示词，想改保存方式就找存储模块，无须在一个大文件里查找所有逻辑。

## 按一次请求读代码

1. 浏览器向 `/api/sessions/{id}/messages` 发送 JSON。
2. `schemas.py` 的 `ChatRequest` 检查 message 是否非空、长度是否合理。Pydantic 会在业务代码运行前拒绝不符合要求的输入。
3. `routes.py` 的 `chat()` 从 URL 取出 ID，拿到这个会话的锁，然后读取记录、组合模型输入。
4. `llm.py` 使用异步客户端请求模型，取得正文。
5. `storage.py` 把本轮用户消息与完整回答一起保存。
6. 路由用 `ApiResponse` 把结果返回浏览器。

`message: str` 是类型提示，主要服务于阅读和工具检查；在 Pydantic 模型中，字段定义还参与运行时校验。普通函数的类型注解不会自动拒绝所有错误类型。

## 为什么配置单独放

`config.py` 的 `Settings` 是配置快照。密钥从环境读取，而不是写入源码或发给浏览器。`Path(__file__).resolve()` 根据文件位置找到项目根目录，所以从其他目录启动也不会找错 `static` 和 `sessions`。

`application.py` 的 `create_app()` 是“工厂函数”：每次调用组装一个应用。测试可以传入临时目录和假模型，因此不用真实 API，也不会碰你的历史记录。这也是为什么模型服务作为参数注入。

## 保存为什么要多一步

直接打开原文件并写入，如果进程中途退出，可能只留下半个 JSON。现在先写同目录临时文件，刷新写入，再用 `os.replace()` 替换原文件。失败时旧文件保留。

锁和原子写入解决不同问题：锁阻止两次请求同时改同一个会话；原子替换避免读到只写了一半的文件。这里的 `asyncio.Lock` 只保护当前进程，所以第一版只运行一个 worker。

输入错误、会话不存在和模型失败也不同：分别返回 400/422、404 和 502/503/504，让页面能提示真正可采取的动作，而不是一律“服务器异常”。

## 自己验证

运行 `python main.py`，打开 `/docs`，用 `POST /api/sessions` 创建会话，然后查看详情。模型密钥没配置时，页面仍能打开，发送消息则得到明确提示。
运行 `python -m pytest tests/test_backend.py -q` 可检查存储、错误和模型模拟行为。

可选练习：在 `schemas.py` 找到名称最大长度，尝试通过 `/docs` 提交超过 60 字符的名称。观察为什么 `rename_session()` 不需要再手写同样的长度检查。
